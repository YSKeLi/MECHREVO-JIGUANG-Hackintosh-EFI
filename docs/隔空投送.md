# Intel 隔空投送配置与实测（2026-11-16）

本次同步采用内置 EFI 的当前配置。测试设备为 Intel AX201、macOS 26.7.2（25G332），手机为 iPhone 14 Pro、iOS 16.3.1。结果仅代表这套组合。

## 当前结果

新版已随 11 月 16 日 10:48:30 的启动加载，日志确认双向成功，同时保留间歇性失败：

| 时间（北京时间） | 事件 | 判断 |
| --- | --- | --- |
| 10:50:05 | 电脑发送收到 UPLOAD 应答、UPLOAD END、Send StateMachine END | 一次完整发送成功 |

| 10:50:34、10:52:35 | 设备发现等待约 45 秒后 Bonjour 超时，失败 Code=1 | 两次失败，未进入文件传输协商 |
| 10:51:59 | 上传流读取错误，随后关闭连接，未见该次完整上传应答 | 不能计为成功，不能认定人为取消 |

系统日志隐藏了设备名称与文件名，方向按本次测试背景判断。源码或接口存在不代表传输完成；StateMachine END 也需要结合上传应答判断。

## 驱动搭配

| 组件 | 当前配置 |
| --- | --- |
| ForbiddenItlwm | 0.5.4-beta.2，Tahoe 版；内部版本号 0.5.4 |
| BTLEAdvFixup | 0.9.1，Tahoe 版 |
| IntelBluetoothFirmware | 2.5.0，启用 |
| BlueToolFixup | 2.7.3，启用 |
| IntelBTPatcher | 文件保留，禁用 |
| AirportItlwm | 文件保留，禁用 |

Lilu 位于 BTLEAdvFixup 之前。两个新增组件只在 Darwin 25.0.0–25.99.99 启用。替换其他 macOS 版本时，需选择对应组件并重新核对系统限制。

本机原有的实验参数已原样保留，不因同步额外添加：

```text
-btleadv -itlawdlcoexprobe -itlawdliface -itlawdlnativeup
-itlawdlcoexrx -itlawdlcoextx -itlawdlcoexmulti -itlawdlcoexdata
-itlawdlmitx -itlawdlelicit -itlawdlcaps -itlawdlsvcmerge -itlawdlawsync
itlawdlintcoal=4 -itlawdlcoexbatx -itlawdlcoexpeerpause
-itlawdlcoexbatrace itlawdltxqueue=4096
```

这些参数是本机配置快照，不是针对所有 Intel 网卡的通用推荐。[固定版本参数说明](https://github.com/retropineaple/ForbiddenItlwm/blob/v0.5.4-beta.2/docs/BOOT-FLAGS.md)

## 已知限制与检查

上游该版本仍列有发送停在“等待”的问题。本机已有成功案例，仍需按具体事务分析失败。接力、通用剪贴板、随航、iPhone 镜像等功能本轮未测，不能从 AirDrop 成功推断它们可用。

检查实际加载版本：

```bash
kmutil showloaded --list-only | grep -E 'ForbiddenItlwm|BTLEAdvFixup'
ifconfig awdl0
```

采集测试时段日志，在发送前后分别记下时间：

```bash
/usr/bin/log show --last 10m --info --style compact \
  --predicate 'process == "sharingd" AND category BEGINSWITH "AirDrop"'
```

让两端保持解锁、靠近，打开 Wi-Fi 与蓝牙，手机接收设为“所有人（10 分钟）”，分别传一个小文件。文件实际接收完成才计为成功。队列错误计数为零也不能代替这一步。

升级系统前，先按上游说明停用 `-btleadv` 并启动一次；同时确认目标系统对应的驱动构建。回退需要一起还原这两个驱动与对应配置，避免只替换一半。
