恢复步骤（2026-11-16）
======================

先判断改动在哪：
1. EFI/config 或 EFI/OC/Kexts 改坏：可从备用 EFI 启动，或进入 Windows 恢复。
2. /Library 中的图形/音频驱动或 AuxKC 改坏：需要 macOS / Recovery 处理；普通 Windows 环境无法直接恢复 APFS 中这些文件。
3. 只出现混合模式内屏黑：先结合显示归属和当前显卡模式判断。该问题仍未修复，历史熄屏／唤醒激活已发生回归，不能把激活脚本作为可靠恢复入口。切独显模式只对独显驱动本身仍可用的情况有帮助；最新证据见“内屏排查更新-20261116.md”。

一、在 Windows 修 EFI

以管理员身份打开命令提示符，确认 S 盘符空闲后：

    mountvol S: /S
    dir S:\EFI

核实挂载的是要恢复的那块磁盘。多磁盘环境需用磁盘管理或 diskpart 进一步核对。

先复制当前出问题的文件留证据，再从自己“已经启动验证过”的备份恢复对应文件。
若一起更新过 config 与驱动，就一起恢复对应版本；若更新过 OpenCore，则 BOOTx64.efi 与 OpenCore.efi 要配套恢复。
保留 EFI\Microsoft 和其他系统引导目录。

    mountvol S: /D

再重启。公开版 config 已清空三码，不能把它当作本机原配置直接覆盖恢复。
旧文档里的 config.plist.GOOD、桌面 before-wex-* 等路径是历史记录，使用前必须确认文件真的存在且适合当前配置。

二、在 macOS 回退

先定位 EFI 分区并挂载，从自己备份中恢复本次改动对应的文件，逐个核对，安全卸载后重启。
隔空投送版本切换涉及 ForbiddenItlwm、BTLEAdvFixup 及其配置项，详见“隔空投送.md”。
EFI 注入驱动的回退不等于重建 AuxKC；本次更新 AirDrop 无需运行内核集合重建。

三、在 Recovery 处理系统驱动

OpenCore 菜单按空格显示辅助条目，选择实际存在的 Recovery / macOS Base System。
用 diskutil list 找到并挂载数据卷；若启用了 FileVault，先解锁。恢复环境的磁盘编号和卷名可能变化。

从自己保存的、匹配同一系统 build 与驱动组合的备份恢复 /Library 中的驱动和 AuxKC；不要从其他机器复制内核集合。
恢复前保存坏文件，恢复后核对 SHA-256 与集合信息。若仍不能启动，应保留日志再判断，不能只凭一条 “No fileset UUID” 推断原因。

历史图形排查保存在“核显驱动方法.md”和“疑难排查记录.md”。其中的偏移、时间和文件名只适用于原记录，不能直接当作今天的恢复目标。
