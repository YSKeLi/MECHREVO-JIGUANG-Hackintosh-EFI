## 阶段 0：先看懂整体结构

核显要工作，需要三部分同时正确：

```
① EFI 层  ── WhateverXe.kext（Lilu 插件）
              负责：准入判断、内核补丁路由、显示钩子
                     ↓
② 系统层  ── /Library/Extensions 里三个 kext
              AppleIntelTGLGraphics            加速器
              AppleIntelTGLGraphicsFramebuffer 帧缓冲（要打二进制补丁）
              AppleIntelTGLCompat              兼容层
                     ↓
③ 资源层  ── /Library/GPUBundles
              ...MTLDriver.bundle   Metal 2
              ...VADriver.bundle    视频硬解
              ...GLDriver.bundle    OpenGL
                     ↓
              全部打包进 AuxKC（内核集合）才会被内核加载
```

**任何一层不对，内屏都不会亮。** 而且改完第 ②③ 层必须重建 AuxKC（阶段 6），否则下次开不了机。

## 阶段 1：准备（备份 + KDK）

### 1.1 确认系统版本

```bash
sw_vers -productVersion    # 26.7.2
sw_vers -buildVersion      # 25G332  ← 记下来，装 KDK 要用
```

### 1.2 安装 KDK（**必须做，否则后面必翻车**）

macOS 13+ 要求所有第三方 kext 打包进 **AuxKC** 并签名封存，重建 AuxKC 需要 **KDK**。缺 KDK 时会生成没有 fileset UUID 的非法集合，后果是**所有 kext 失效、系统起不来**。

```bash
# 1) 从社区镜像下载与 build 完全一致的 KDK（不需要开发者账号）
#    https://github.com/dortania/KdkSupportPkg/releases
#    本机对应：Kernel_Debug_Kit_26.7.2_build_25G332.dmg   (1126 MB)

# 2) 安装
hdiutil attach ~/Downloads/Kernel_Debug_Kit_26.7.2_build_25G332.dmg
sudo installer -pkg "/Volumes/Kernel Debug Kit/KernelDebugKit.pkg" -target /
hdiutil detach "/Volumes/Kernel Debug Kit"

# 3) 验证
ls /Library/Developer/KDKs/
# 期望：KDK_26.7.2_25G332.kdk
```

> 网络慢的话可以用镜像加速前缀，例如 `https://gh-proxy.com/` + 原始 GitHub 链接（实测 13 MB/s）。

### 1.3 完整备份（**这一步决定你能不能回滚**）

```bash
# 内核集合
sudo cp /Library/KernelCollections/AuxiliaryKernelExtensions.kc \
        ~/Downloads/AuxKC.before-igpu-$(date +%Y%m%d-%H%M%S).kc

# 三个核显 kext + GPUBundles
mkdir -p ~/Downloads/igpu-backup
sudo ditto /Library/Extensions/AppleIntelTGLGraphics.kext           ~/Downloads/igpu-backup/AppleIntelTGLGraphics.kext
sudo ditto /Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext ~/Downloads/igpu-backup/AppleIntelTGLGraphicsFramebuffer.kext
sudo ditto /Library/Extensions/AppleIntelTGLCompat.kext             ~/Downloads/igpu-backup/AppleIntelTGLCompat.kext
sudo ditto /Library/GPUBundles                                      ~/Downloads/igpu-backup/GPUBundles

# EFI（挂 ESP 后打包）
sudo mkdir -p "/Volumes/NO NAME"
sudo /sbin/mount_msdos /dev/disk0s1 "/Volumes/NO NAME"
ditto -c -k --keepParent "/Volumes/NO NAME/EFI" ~/Downloads/EFI-full-$(date +%Y%m%d).zip
diskutil unmount "/Volumes/NO NAME"
```

### 1.4 记录基线

```bash
# 内屏现在归谁
ioreg -l -w0 | grep 'IODisplayPrefsKey" ='

# 加速器是否存在
ioreg -w0 -c IntelAccelerator | grep -c 'class IntelAccelerator'

# 当前内核集合 UUID
kmutil inspect | grep 'auxiliary kext collection'
```

## 阶段 2：BIOS 设置

| 项目 | 设置 | 说明 |
|---|---|---|
| **显卡模式** | **混合模式 / MSHybrid** | 独显直连模式下核显无法驱动内屏 |
| Secure Boot | **关闭** | 否则加载不了 OpenCore |
| CFG Lock | 关闭 | 或用 `AppleXcpmCfgLock`（本配置已启用） |
| VT-d | 关闭 | 或用 `DisableIoMapper`（本配置已启用） |
| 显存 DVMT | 尽量 ≥ 60 MB | 本机固件固定 60 MB，靠补丁撑起 |
| Fast Boot | 关闭 | 否则可能跳过 OpenCore |
| CSM | 关闭 | — |

> ⚠️ 改完 BIOS 建议**冷启动**（关机拔电 15 秒），有些机型的 MUX/显示初始化只在冷启动时重做。

## 阶段 3：EFI 配置

### 3.1 放入 WhateverXe.kext

```
EFI/OC/Kexts/WhateverXe.kext
```

在 `config.plist` 的 `Kernel → Add` 中启用，**必须排在 Lilu 之后**：

```
Lilu.kext            ← 先
WhateverXe.kext      ← 后
```

### 3.2 boot-args

```
-igfxdvmt -v debug=0x100 keepsyms=1 -vi2c-force-polling ctrsmt=full -ibtcompatbeta
revpatch=sbvmm,cpuname nvfb=1 nvaccel=1 nvfbheads=4 -nvkmsnosmooth
amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0 gfxrst=4 revcpu=1
-allow3d -disablegfxfirmware
```

核显相关：

| 参数 | 作用 |
|---|---|
| `-igfxdvmt` | 忽略固件 DVMT，使用补丁值 |
| `-allow3d` | 允许 3D 加速 |
| `-disablegfxfirmware` | 不加载 GuC 固件 |
| `amfi_get_out_of_my_way=0x1` + `amfi=0x80` | 关闭 AMFI，加载未签名 kext |

### 3.3 iGPU 的 DeviceProperties

`DeviceProperties → Add → PciRoot(0x0)/Pci(0x2,0x0)`：

```xml
<key>framebuffer-patch-enable</key><data>AQAAAA==</data>   <!-- 01000000 -->
<key>framebuffer-stolenmem</key><data>AAAAAwA=</data>      <!-- 0000C003 = 60 MB -->
```

### 3.4 Kernel → Block（可选）

```
Identifier: com.apple.iokit.IONDRVSupport
Strategy:   Exclude
```

作用有限——`Strategy: Exclude` 和 `Disable` 都**挡不住系统内核集合里的 kext**，只能拦 OpenCore 注入的。保留它无副作用。

### 3.5 校验配置

```bash
plutil -lint "/Volumes/NO NAME/EFI/OC/config.plist"
```

## 阶段 4：安装核显驱动组件

### 4.1 获取 WhateverXe Graphics payload

从 `b00t0x/WhateverXe-Graphics` 下载源码包，解压后得到：

```
WhateverXe-Graphics-main/
└── payloads/
    ├── Big Sur/  Monterey/  Ventura/  Sonoma/  Sequoia/  Tahoe/  Common/
    └── ...
```

macOS 26 用 **Tahoe** + **Common**。

### 4.2 安装（完整脚本）

```bash
#!/bin/bash
# 安装 WhateverXe Graphics payload（Tahoe + Common）
set -euo pipefail
[ "$EUID" -eq 0 ] || { echo "请用 sudo 运行"; exit 1; }

SRC="$HOME/Downloads/wxg/WhateverXe-Graphics-main/payloads"
[ -d "$SRC/Tahoe" ] || { echo "找不到 payload: $SRC"; exit 1; }

BK="$HOME/igpu-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BK"

echo "== 1/5 备份 =="
ditto /Library/GPUBundles/AppleIntelTGLGraphicsMTLDriver.bundle "$BK/" 2>/dev/null || true
ditto /Library/Extensions/AppleIntelTGLCompat.kext              "$BK/" 2>/dev/null || true
ditto /Library/Extensions/AppleIntelTGLGraphics.kext            "$BK/" 2>/dev/null || true
ditto /Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext "$BK/" 2>/dev/null || true
echo "   备份到 $BK"

echo "== 2/5 安装 Tahoe payload =="
ditto "$SRC/Tahoe/Library" /Library

echo "== 3/5 安装 Common payload（Compat 0.7.0）=="
ditto "$SRC/Common/Library" /Library

echo "== 4/5 修正权限 =="
chown -R root:wheel /Library/GPUBundles/AppleIntelTGLGraphics*.bundle \
                    /Library/Extensions/AppleIntelTGL*.kext 2>/dev/null || true
chmod -R go-w /Library/GPUBundles/AppleIntelTGLGraphicsMTLDriver.bundle \
              /Library/Extensions/AppleIntelTGLCompat.kext 2>/dev/null || true

echo "== 5/5 重建内核集合 =="
sudo /usr/bin/kmutil create -n aux --volume-root / \
  --allow-missing-kdk --kernel /System/Library/Kernels/kernel \
  -B /System/Library/KernelCollections/BootKernelExtensions.kc \
  -S /System/Library/KernelCollections/SystemKernelExtensions.kc \
  --repository /Library/Extensions \
  -A /Library/KernelCollections/AuxiliaryKernelExtensions.kc -z

echo "== 完成 =="
echo "  MTL 驱动 SHA: $(shasum -a 256 /Library/GPUBundles/AppleIntelTGLGraphicsMTLDriver.bundle/Contents/MacOS/AppleIntelTGLGraphicsMTLDriver | cut -c1-16)"
echo "  Compat 版本: $(plutil -extract CFBundleVersion raw /Library/Extensions/AppleIntelTGLCompat.kext/Contents/Info.plist)"
```

### 4.3 验证安装

```bash
# 三个 kext 版本
for k in AppleIntelTGLGraphics AppleIntelTGLGraphicsFramebuffer AppleIntelTGLCompat; do
  printf "  %-42s %s\n" "$k" "$(plutil -extract CFBundleVersion raw /Library/Extensions/$k.kext/Contents/Info.plist)"
done
# 期望：16.0.0 / 16.0.0 / 0.7.0

# 三个 bundle 是否存在
ls -1 /Library/GPUBundles | grep AppleIntelTGL
# 期望：VADriver / MTLDriver / GLDriver
```

> **为什么要用 0.4.0 的 payload**：旧版 payload 在 macOS 26 上会导致 Metal 崩溃 / WindowServer 重启。0.4.0 修了这个问题。

## 阶段 5：二进制补丁

> 只针对 `AppleIntelTGLGraphicsFramebuffer`，因为固件的 DVMT 值不符合 Apple 的公式。

### 5.1 备份原文件

```bash
B=/Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext/Contents/MacOS/AppleIntelTGLGraphicsFramebuffer
sudo cp -p "$B" ~/Downloads/AppleIntelTGLGraphicsFramebuffer.orig
```

### 5.2 补丁 ①：DVMT 显存写死 60 MB

**原因**：固件 GGC = `0xFEC7`，高字节 `0xFE` → 60 MB 预分配。Apple 的公式假设 32 MB 整数倍，算出的值与实际不符 → `Insufficient stolen memory` / `IGStolenMemoryPool = 0` / `IOAccelTask::release` panic。

```asm
原始：
  0x42DA1: C1 E0 11           shll $0x11, %eax        ; 只保留高 7 位
  0x42DA4: 25 00 00 00 FE     andl $0xFE000000, %eax
补丁：
  0x42DA1: 90 90 90           nop × 3
  0x42DA4: B8 00 00 C0 03     movl $0x03C00000, %eax  ; 60 MB
```

### 5.3 补丁 ②：AUX 电源井不关闭

**原因**：`AppleIntelPowerWell::init()` 会把固件已开启的 AUX/DDI 电源井强行关闭。

```asm
原始：
  0x5A471: E8 94 09 00 00     call disablePowerWellAux
补丁：
  0x5A471: 90 90 90 90 90     nop × 5
```

> ⚠️ 日志 `EFI should not enable AUX0 power well - overriding` **打印在关闭动作之前**，所以打完补丁这条日志依然出现。**不要用它判断补丁是否生效**，要看字节。

### 5.4 打补丁（Python，别用 sed）

```bash
sudo python3 - <<'PY'
import pathlib
p = pathlib.Path('/Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext/Contents/MacOS/AppleIntelTGLGraphicsFramebuffer')
b = bytearray(p.read_bytes())
b[0x42DA1:0x42DA4] = bytes([0x90,0x90,0x90])
b[0x42DA4:0x42DA9] = bytes([0xB8,0x00,0x00,0xC0,0x03])
b[0x5A471:0x5A476] = bytes([0x90]*5)
p.write_bytes(bytes(b))
print("已写入")
PY
```

### 5.5 重新签名

```bash
sudo codesign -f -s - /Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext
codesign -v /Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext && echo "签名 OK"
```

### 5.6 验证字节

```bash
B=/Library/Extensions/AppleIntelTGLGraphicsFramebuffer.kext/Contents/MacOS/AppleIntelTGLGraphicsFramebuffer
xxd -s 0x42DA1 -l 3 -p "$B"    # 909090
xxd -s 0x42DA4 -l 5 -p "$B"    # b80000c003
xxd -s 0x5A471 -l 5 -p "$B"    # 9090909090
```

## 阶段 6：重建内核集合

**改了 `/Library/Extensions` 里任何 kext 或二进制之后，这一步必须做，否则下次开不了机。**

```bash
sudo /usr/bin/kmutil create -n aux --volume-root / \
  --allow-missing-kdk --kernel /System/Library/Kernels/kernel \
  -B /System/Library/KernelCollections/BootKernelExtensions.kc \
  -S /System/Library/KernelCollections/SystemKernelExtensions.kc \
  --repository /Library/Extensions \
  -A /Library/KernelCollections/AuxiliaryKernelExtensions.kc -z
```

### 关键参数

| 参数 | 作用 | 漏了会怎样 |
|---|---|---|
| `--kernel /System/Library/Kernels/kernel` | 用真实内核二进制解析内核符号 | 符号绑定不完整，驱动行为异常 |
| `--volume-root /` | 以根卷为基准解析路径 | 路径解析可能失败 |
| `--repository /Library/Extensions` | 第三方 kext 来源 | 找不到 kext |
| `-z` | 跳过授权检查 | 第三方 kext 无 Apple 签名，会被拒 |
| `--allow-missing-kdk` | 无 KDK 时降级 | 有 KDK 时无影响 |

### 验证（**必须带 UUID**）

```bash
kmutil inspect | grep 'auxiliary kext collection'
# 正常：auxiliary kext collection at /Library/.../AuxiliaryKernelExtensions.kc (6A54DC47-...)
# 异常：括号里没有 UUID
```

```bash
# 确认 8 个关键组件都在
kmutil inspect -a x86_64 -A /Library/KernelCollections/AuxiliaryKernelExtensions.kc | grep -E 'TGL|b00t0x|nullmoth'
```

> 每次成功重建 UUID 都会变，这是正常的。**没有 UUID 才是错的。**

## 阶段 8：激活内屏

### 8.1 正确操作

```bash
pmset displaysleepnow
```

**然后 2 秒内按一下空格键。**

或用脚本（内含模拟按键 + 结果自检）：

```bash
bash scripts/激活内屏.sh
```

### 8.2 为什么必须"短 Doze"（核心结论）

| Doze 持续时长 | 结果 | 实测时间 |
|---|---|---|
| **1.0 秒** | ✅ 成功 | 11-07 14:07 |
| **1.6 秒** | ✅ 成功 | 11-06 15:31 |
| 5.8 秒 | ❌ 失败 | 11-07 12:09 |
| 20.0 秒 | ❌ 失败 | 11-07 12:08 |
| 42.2 秒 | ❌ 失败 | 11-07 12:26 |
| 57.8 秒 | ❌ 失败 + DBUF 超时 | 11-07 13:50 |

**阈值在 2～5 秒之间。**

```
短 Doze（≤2 秒）
  面板电源没真正断，eDP 链路保持
  → 唤醒不需要重新训练 → 直接点亮 ✅

长 Doze（>5 秒）
  面板深度断电（DBUF 显示缓冲电源井也掉电）
  → 唤醒必须重新训练链路 → 训练要读写面板 DPCD → 走 AUX
  → AUX 在这台机器上不通 → 超时 → Phase 1 失败
  → 驱动通知 AGDC 把显示下线 → FB0 is not enabled → 只能重启 ❌
```

### 8.3 ❌ 错误做法（我踩过的坑）

```bash
# 千万不要这样
pmset displaysleepnow
sleep 3                 # ← Doze 被拉长
caffeinate -u -t 2      # ← 这个【不能】唤醒屏幕！
```

`caffeinate -u` 只是"阻止系统休眠"，不会点亮已经睡着的显示器。屏幕会一直黑到你手动碰键盘，间隔被拉到几十秒 → **必然失败**。

### 8.4 成功与失败的日志

**成功**（间隔 1.0 秒）：

```
14:07:25.084  FB0: power state transition Wake --> Doze
14:07:26.040  FB0: power state transition Doze --> Wake
14:07:26.474  FB0: Complete modeset
              （无 AUX 超时、无训练失败、无 FB0 禁用）
```

**失败**（间隔 57.8 秒）：

```
13:50:41  [ERROR][DISPLAY] DBUF 2 power up timeout
13:50:41  [ERROR][AUX] ddi = 0 Time out: 0x8d40023f
13:50:42  [ERROR][LINK_TRAINING] writeAUX failed: 0xe00002d6
13:50:42  [ERROR][LINK_TRAINING] writeAUX failed: 0xe00002d8
13:50:42  [ERROR][LINK_TRAINING] readAUX failed: 0xe00002d6
13:50:42  [ERROR][LINK_TRAINING] Phase 1 of link training failed
                                  - notifying AGDC to take display offline
13:50:42  [ERROR][DISPLAY] FB0: Hardware mode set failed, err = 0xe00002bc
13:50:43  [ERROR][DISPLAY] FB0 is not enabled
```

### 8.5 失败后

**只能重启。** `FB0 is not enabled` 出现后面板彻底关闭（连背光都没有），软件无法恢复。

## 阶段 9：最终配置与日常使用

### 9.1 每次开机的固定流程

```
1. 确认外屏已连接、BIOS 是混合模式
2. 开机，等系统起来
3. 内屏只有背光（正常）
4. bash scripts/激活内屏.sh
   或：pmset displaysleepnow → 2 秒内按空格
5. 内屏点亮 2560×1600 `60Hz`
```

### 9.2 把外屏设为主屏

系统设置 → 显示器 → 拖拽排列，把菜单栏拖到外屏。

或用 CoreGraphics 命令（强制排列）：

```swift
// 外屏放 (0,0) = 主屏，内屏放外屏右边
CGBeginDisplayConfiguration(&cfg)
CGConfigureDisplayOrigin(cfg, externalID, 0, 0)
CGConfigureDisplayOrigin(cfg, internalID, Int32(externalWidth), 0)
CGCompleteDisplayConfiguration(cfg, .permanently)
```

### 9.3 刷新率

| 屏 | 刷新率 | 说明 |
|---|---|---|
| 内屏（核显） | **60 Hz** | 核显路径只提供 60 Hz，无法 180 Hz |
| 外屏（独显） | 144 Hz | — |

驱动重装会把刷新率重置为 60 Hz，需要重新设置。

### 9.4 音频与 Siri 的取舍（本机实测）

| 音频驱动 | 输出设备 | 内屏激活 | Siri |
|---|---|---|---|
| **VoodooHDA 3.0.2** | 模拟输出（无 HDMI） | ✅ 可用 | ✅ 可用 |
| NMXAudio（NVIDIA 2.7+ 自带） | 4 个（含 HDMI/DP） | ✅ 可用 | ❌ 报"无法连接麦克风" |

**本机最终选择：VoodooHDA**（内屏和 Siri 同时可用）。

NMXAudio 的 Siri 问题原因：它在 CoreSpeech 的音频会话重配置时执行
`Abandoning I/O cycle because reconfig pending`，只交付约 150 ms 音频
（`total chunks received: 5, samples: 2390`），端点检测判定无输入 → 报错。属驱动实现缺陷，上游未修复（提交历史里无相关修改）。

## 阶段 10：问题与解决方案总览

### P1 加速器起不来（IntelAccelerator = 0）

**现象**：

```bash
ioreg -w0 -c IntelAccelerator | grep -c 'class IntelAccelerator'   # 0
```

WEX 属性显示未准入：

```
TGLAcceleratorAdmissionReady = No
```

**原因**：WEX 的准入是 27 个条件的逻辑与（`surfaceABIReady && adlnObserved && skuReady && ...`），任一为 false 就整体不过。

**排查顺序**：

1. 内核集合是否合法（有 UUID）→ 阶段 6
2. 三个 TGL kext 是否都在 AuxKC 里 → `kmutil inspect`
3. 显存补丁是否在位（`Insufficient stolen memory` + `IGStolenMemoryPool = 0` 会导致 panic）→ 阶段 5.2
4. 是否被 `IONDRVFramebuffer` 抢占 → P5

**已知结论**：多屏幕（接外屏）时准入更容易通过；单屏时容易卡在 `TGLBootstrapAUXReady = No`。

---

### P2 Metal 设备只有 NVIDIA

**现象**：`MTLCopyAllDevices()` 只返回 NVIDIA。

**原因**：

- 核显加速器没实例化（见 P1）
- 或 launchd 会话里 Metal 只注册了独显

**解决**：先修 P1。核显加速器起来后 Metal 设备会自动出现。

---

### P3 内屏归独显（PEGP@0）

**现象**：

```bash
ioreg -l -w0 | grep 'IODisplayPrefsKey" ='
# IOService:/.../PEGP@0-...
```

**原因**：

- BIOS 是独显直连，不是混合模式
- 或混合模式下核显初始化失败，系统回落到独显

**解决**：

1. 确认 BIOS 是混合模式
2. 确认接了外屏（单屏时核显无法初始化）
3. 用阶段 8 的方法激活

---

### P4 Insufficient stolen memory

**现象**：每次开机都报这条，但内屏能正常点亮。

**原因**：固件 GGC = `0xFEC7`（60 MB），不符合 Apple 的 32 MB 整数倍公式。

**判断**：

| 情况 | 处理 |
|---|---|
| 只报这一条，其他正常 | **可以忽略** |
| 伴随 `IGStolenMemoryPool = 0` | 补丁没生效，检查阶段 5.2 |
| 伴随 `IOAccelTask::release` panic | 同上，并检查 `framebuffer-stolenmem` |

---

### P5 IONDRVFramebuffer 抢占核显

**现象**：

```
IGPU@2
└── IONDRVFramebuffer     ← 通用 NDRV 驱动占住了核显
```

**原因**：`IONDRVFramebuffer` 有 `IONameMatch="display"`（score 20000）和 `IOPCIClassMatch 0x03000000` 兜底规则；`AppleIntelFramebufferController` 的 score 更高（80000）但在 AuxKC 里加载更晚 —— 谁先 probe 谁赢。

**三种方案全部无效**（已验证）：

| 方案 | 结果 |
|---|---|
| `Kernel → Block` 的 `Strategy: Exclude → Disable` | ❌ Block 管不了系统 KC 里的 kext |
| 改 iGPU 的 `IOName = "IGPU"` | ❌ 还有 class 兜底规则 |
| 静态改二进制改 score | ❌ 破坏签名 → AuxKC 非法 → 开不了机 |

**实际解法**：确保 AuxKC 合法 + 接外屏，让核显正常初始化，抢占概率自然降低。

---

### P6 内屏只有背光（开机不亮）

见 [阶段 8](#阶段-8激活内屏)。核心：短 Doze 激活。

---

### P7 激活后彻底黑屏（FB0 is not enabled）

**原因**：Doze 太长 → 链路训练失败 → 驱动下线显示。

**解决**：**只能重启**。之后改用短 Doze。

---

### P8 不接外屏时内屏永远点不亮

**现象**：AUX 超时 630 次，面板无反应。

**原因**：单显示设备时核显显示管道初始化路径不通。

**解决**：

1. 接外屏
2. 或用 **HDMI 假负载**（dummy plug，20-40 元）欺骗系统
3. ❌ 不要用 BetterDisplay 等软件虚拟显示器——实测在本机初始化 NVIDIA Metal 时 SIGILL 崩溃

---

### P9 AUX Time out / writeAUX failed / Phase 1 failed

| 日志 | 含义 | 处理 |
|---|---|---|
| `AUX Time out: 0x8d40023f` | DDI 0（内屏）AUX 读超时 | Doze 太长，重启后改短 Doze |
| `writeAUX failed: 0xe00002d6` | 写 DPCD 失败 | 同上 |
| `writeAUX failed: 0xe00002d8` | 写 DPCD 失败（另一种状态） | 同上 |
| `readAUX failed: 0xe00002d6` | 读 DPCD 失败 | 同上 |
| `Phase 1 of link training failed` | 时钟恢复/均衡失败 | 同上 |

---

### P10 DBUF 2 power up timeout

**含义**：显示缓冲（DBUF）电源井上电超时。

**原因**：长 Doze 后面板深度断电，电源井无法按时恢复。

**处理**：重启；之后用短 Doze。

---

### P11 改分辨率无法点亮内屏

**现象**：`CGDisplaySetDisplayMode` 切换分辨率后内屏不亮，日志里 **0 条 TGL 记录**。

**原因**：改分辨率不触发驱动重新初始化。

**结论**：**只有电源状态转换（Doze→Wake）会触发完整初始化。** 别浪费时间试分辨率。

---

### P12 内核集合重建后开不了机

**现象**：卡登录界面 / WindowServer 无响应（远程桌面能进）。日志：

```
kernelmanagerd: No fileset UUID for auxKC
kernelmanagerd: Img4 error: format neither im4p nor img4
kernelmanagerd: invalid codeful kernel extension: com.nullmoth.NVRMAGDC ...
```

**原因**：缺 KDK，或重建参数不对 → 内核集合非法 → 所有 codeful kext 插入失败。

**解决**：

1. 装对应 build 的 KDK（阶段 1.2）
2. 用正确参数重建（阶段 6）
3. 验证 UUID 存在
4. 仍不行 → 阶段 11 恢复

---

### P13 「EFI should not enable AUX0 power well」

**含义**：驱动要关闭固件已开启的 AUX0 电源井。

**⚠️ 判断陷阱**：这条日志打印在**关闭动作之前**，所以即使 NOP 掉了动作，日志照样出现。**不要用它判断补丁是否生效**，要看二进制字节（阶段 5.6）。

---

### P14 Wrong CD clock frequency 0x42603000

**含义**：EFI 设置的 CDCLK 与驱动期望不一致。

**影响**：本机实测无影响，可忽略。

## 阶段 11：回滚与灾难恢复

### 11.1 能进系统时回滚

```bash
# 恢复内核集合（用备份重建，不能直接 cp——文件带 restricted 标志）
sudo /usr/bin/kmutil create -n aux --volume-root / \
  --allow-missing-kdk --kernel /System/Library/Kernels/kernel \
  -B /System/Library/KernelCollections/BootKernelExtensions.kc \
  -S /System/Library/KernelCollections/SystemKernelExtensions.kc \
  --repository /Library/Extensions \
  -A /Library/KernelCollections/AuxiliaryKernelExtensions.kc -z

sudo reboot
```

### 11.2 进不去系统 → 用 Recovery（**不需要 U 盘**）

1. 开机，停在 OpenCore 菜单
2. **按空格键** —— Recovery 属于辅助条目，默认隐藏
3. 选 `macOS Base System` / `Recovery`
4. 实用工具 → 终端

```bash
diskutil list                       # 找数据卷（本机 "MacOS - 数据" = disk1s1）
diskutil mount disk1s1

DATA="/Volumes/MacOS - 数据"
KC="$DATA/Library/KernelCollections/AuxiliaryKernelExtensions.kc"

# 备份坏的
cp "$KC" "$DATA$HOME/Downloads/AuxKC.broken-$(date +%H%M%S).kc"

# 覆盖（Recovery 里 SIP 较宽松）
cp "$DATA$HOME/Downloads/AuxKC.before-igpu-*.kc" "$KC"
# 若报 Permission denied：
chflags norestricted "$KC" && cp ... "$KC"

# 校验
shasum -a 256 "$KC"
```

### 11.3 最省事的兜底

**BIOS 切独显直连** —— 内屏 180 Hz 正常，完全不依赖核显驱动。

### 11.4 从 Windows 修（只能修 EFI）

| 能做 | 不能做 |
|---|---|
| ✅ 恢复 `config.plist` | ❌ 碰 APFS（内核集合、`/Library` 驱动） |
| ✅ 改 boot-args、`PickerMode` | |
| ✅ 替换 EFI 里的 kext / OpenCore.efi | |

```cmd
diskpart
list disk
select disk 0
list partition
select partition 1
assign letter=Z
exit
dir Z:\EFI\OC
```
